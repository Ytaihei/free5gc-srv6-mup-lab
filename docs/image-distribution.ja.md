# コンテナイメージの配布レビュー

[English](image-distribution.md) | 日本語

## 対象範囲と判断の分離

ソース公開、ローカルでのラボ利用、コンテナイメージの再配布は別々の判断です。この手順は**非公開のレビュー資料**を準備します。イメージ公開、リリース承認、法的適合性の認証、すべての脆弱性候補の悪用可能性の確認を行うものではありません。生成物はGitHubのリリースに添付せず、除外済みの`.lab/`内に保持してください。[第三者ソフトウェアの通知](../THIRD_PARTY_NOTICES.ja.md)にあるソースのみの配布方針は継続します。

最初のイメージ検査ではソース用のライセンス許可リストを暫定利用したため、一般的なGPL/LGPLのOSパッケージも「禁止」ではなく「未審査」として不合格になりました。イメージ検査は現在、専用の[image-distribution-policy.yml](../config/image-distribution-policy.yml)を使用します。ソースCIは従来の別ポリシーを変更せず使用します。

## 依存更新

[compact-dependencies.json](../config/compact-dependencies.json)は、コンパクト構成の外部Goビルドで使用する最低バージョンをx/crypto 0.55.0、x/net 0.60.0、x/text 0.41.0、gRPC 1.83.2に固定します。独自プロジェクトのmodule lockは適用対象の新しいバージョンをすでに選択しています。外部ソースはビルド用の作業領域にコピーしてから更新し、ホスト側の編集可能なworktreeを保持します。利用者が指定した、より新しい安定版は維持します。これらの対象moduleにreplaceやプレリリース／疑似バージョンがある場合は、黙って上書きせずレビューを要求します。実効module lockと依存ポリシー・実装のハッシュを各ビルド記録に保存します。初回のVinbero構築も同じ最低バージョン確認を使用します。6VMの参照構成は変更しません。

ビルダーは引き続き固定済みのGo/Node/Yarnを使用します。未使用のnpm/npxは独立したtoolchainステージで除去し、npmもダウンロード元アーカイブも最終ビルダーのレイヤーに入りません。Yarnを直接呼び出します。Goのプラットフォーム証明書検証用の鍵fixtureは、正確なハッシュを確認して最終ステージのCOPY前に除去します。他の公開SDKテスト用fixtureは引き続き検査・由来確認の対象で、秘密情報検査の免除ではありません。

上流イメージにNFバイナリを重ねるだけでは、OS・コンパイラー・古いレイヤーは置き換わりません。明示的なclean-runtimeオプションは、固定済みのコンパクト構成用UbuntuベースからNF/WebUIを作り直します。新しくビルドした成果物だけをコピーし、設定・証明書は実行時のマウントに残します。UPFの経路設定コマンド、WebUIのフロントエンド、既存のDB状態、イメージ切り替え試験とロールバックは維持します。DB移行や証明書のローテーションではありません。

```bash
./lab rebuild vinbero
./lab rebuild free5gc-smf --clean-runtime
./lab health
./lab test all
./lab audit-images --scan
```

この構成をレビューする場合、対応するfree5GCの11コンポーネントそれぞれにclean-runtimeオプションを使用します。MongoDBや独自ラボコンポーネントには使用できません。通常のrebuildは従来どおり親イメージを継承します。現在の初回デプロイでは11個すべてのNFをクリーンなランタイムベースから自動構築し、Vinberoの依存を更新した共通ランタイムも新しく作ります。ビルドとCompose検証が成功した後に一式を選択し、開発用の独自指定には書き込みません。既存の独自指定と旧候補は保持し、すでに稼働している古いイメージを暗黙に更新しません。実際の構成ごとに個別に監査してください。Aptリポジトリはスナップショット固定ではないので、実際の成果物ごとに導入バージョンとイメージdigestを保持してください。

## 鍵の由来確認は検査除外ではない

最初の19イメージ検査の10件は、ファイル名や正規表現の一部分ではなく、ファイル全体のSHA-256で照合しました。

- free5GC証明書ディレクトリ内の9件は、[固定済みComposeの証明書ツリー](https://github.com/free5gc/free5gc-compose/tree/e4e2acebad6d6a8c49cfb03a97d9a09dd40c55c7/cert)で公開されている既定鍵と一致します。[上流NRFイメージのレシピ](https://github.com/free5gc/free5gc-compose/blob/e4e2acebad6d6a8c49cfb03a97d9a09dd40c55c7/nf_nrf/Dockerfile)も既定鍵をイメージへコピーしています。
- Go SDKの1件は[プラットフォーム証明書検証のテスト](https://github.com/golang/go/blob/go1.26.9/src/crypto/x509/platform_test.go)で使用されるもので、運用者の認証情報ではありません。

[public-test-keys.json](../config/public-test-keys.json)にパス・ハッシュ・上流の出所を記録し、鍵そのものは含めません。資料収集時に保存イメージのレイヤーと照合し、変更・欠落・別パスの鍵は未確認のまま残します。秘密情報検査の除外は追加しません。公開済みの鍵を本番認証に使用してはいけません。新しいNFレイヤーには鍵を埋め込みませんが、隔離ラボの実行時証明書マウントは変更しておらず、イメージ検査の対象外です。後続レイヤーで鍵を削除しても古いレイヤーに残るため、削除だけでは配布物の秘匿情報除去になりません。

## イメージ用ライセンス基準

これはエンジニアリング上の確認表です。実際の要件は正確な本文、改変・リンク方法、配布／サービス提供の形態によります。既知の識別子は確認資料の分類に使うだけで、パッケージやイメージ全体の配布を承認しません。すべての検査指摘を保持し、配布前に適切なライセンスレビューを行ってください。

| ライセンス区分 | 確認が必要な資料 |
|---|---|
| MIT、BSD、Apache、ISCなど通知型の既知ライセンス | 正確なライセンス・著作権・NOTICE本文と改変記録 |
| MPL | 上記と対象ファイルのソース |
| LGPL | 対応ソースとリンク／再リンク方法の確認 |
| GPL | 対応ソース、改変、ビルド・導入スクリプト |
| AGPL | GPL系の資料とネットワーク経由のソース入手方法の確認 |
| SSPL / MongoDB | 正確なソース・通知と配布／サービス範囲の明示的レビュー |
| メタデータ不明、曖昧な識別子、複合式、public-domainの表示 | 正確なパッケージ・バージョン・ファイルのライセンス特定。自動的な読み替えや承認はしない |

実装は`distribution_approved`と`publication_approved`をfalseのまま保持します。修正版のないものを含むHIGH/CRITICAL候補、秘密情報パターン、ライセンス不明、成果物の同一性不一致は引き続きスキャナーの判定を不合格にします。ライセンス分類・収集完了・公開承認は別フィールドです。既知のGPL識別子であること自体は、スキャナーの不合格理由ではなくなります。対象パッケージのレビューでは[GPLv2本文](https://www.gnu.org/licenses/old-licenses/gpl-2.0.txt)、[AGPLv3本文](https://www.gnu.org/licenses/agpl-3.0.txt)、[MongoDB SSPL本文](https://www.mongodb.com/legal/licensing/server-side-public-license)、[Debianのcopyrightファイル方針](https://www.debian.org/doc/debian-policy/ch-docs.html#copyright-information)を確認してください。これらのリンクはソース提供の申し出ではありません。

## 非公開資料の収集

完了済みイメージ検査に対して実行します。スキャナーのポリシー判定が不合格でも使用できますが、検査未完了、アーカイブ・レポート・SBOMのハッシュ変更は拒否します。

```bash
python3 scripts/image-materials.py .lab/VM_NAME/image-audits/RUN
python3 scripts/image-materials.py .lab/VM_NAME/image-audits/RUN \
  --download-go-sources --go /absolute/path/to/locked/go
```

プレースホルダーを実際の非公開検査結果と固定済みGoの実行ファイルに置き換えてください。2番目は公開Goプロキシとchecksumデータベースから、正確なバージョンのmoduleアーカイブを明示的にダウンロードします。取得ソースをビルドすることはありません。不明・不正なバージョンは黙って別タグに置き換えず、収集失敗として残します。どちらも`.lab/distribution-materials/`配下に新しい非公開ディレクトリを作成し、権限は0700、ファイルは0600とします。古い検査記録を保持します。

資料には、イメージごとのパッケージ・バージョン・ソースパッケージ一覧、ライセンス分類と要件、実際のSBOM、イメージ・レイヤーの識別情報、鍵の由来分類、保存済み全レイヤーから集めた内容ハッシュ別のライセンス・通知本文が含まれます。任意で取得するmodule ZIPはmodule全体のソースとchecksumの識別情報を保持し、ライセンス・NOTICEも収集します。アーカイブ内のパスやリンクをホストのファイルシステムに展開せず、鍵の内容を通知本文の保存先へコピーしません。最終rootfsを再構成する収集器ではないため、古いレイヤーの通知や未解決のリンクにはレビューが必要です。

`materials.json`に証跡・ポリシー・実装のハッシュ、収集結果、残項目を記録します。`complete`は一覧走査が完了したことを示し、必要なソースとライセンスがすべて揃ったことではありません。moduleの状態と`collection_failures`も確認してください。module収集失敗時は終了コードを非0にします。main moduleのバージョンが不明な場合は、架空のリリースタグではなく実際のビルド用ソーススナップショットが必要です。

最初の資料準備では19イメージ、レイヤー単位の通知1,750件、異なる通知本文489件を整理しました。バージョンのあるGo module 200件のうち198件でソースと通知を取得し、1件は取得ZIPにライセンスファイルを検出できず、1件は報告されたバージョンで取得できませんでした。これは確認不足として残します。afero-snd 0.1.0はライセンス本文の確認が必要で、報告されたgosu 1.19.0はGo moduleタグとして解決できません。似たバージョンを実バイナリとの照合なしに代用してはいけません。この旧一覧は後の再ビルド済みイメージの証明ではないため、最終検査結果に対して再収集してください。

## 配布資料の受け入れチェックリスト

イメージやバイナリを添付する前に、次を保持・確認してください。

1. 正確なイメージ・プラットフォーム・レイヤーdigest、新しいSBOM、検査DBの識別情報。
2. 含まれる全コンポーネント、OSパッケージ、静的ライブラリ、eBPFオブジェクト、フロントエンド資産、toolchain依存。スキャナーの検出範囲は一様ではありません。
3. 成果物のバージョンに対応するライセンス・著作権・NOTICE本文。
4. 正確な対応ソース、ローカルパッチ、実効dependency lock、ビルド・導入スクリプト。OSパッケージでは上流URLだけでなく正確なソースパッケージとディストリビューションのパッチを保持します。ソース提供の申し出を使用する場合は別途確認してください。このスクリプトは申し出を行いません。
5. 改変済みmain programのソーススナップショットとC/C++/eBPF入力。対象成果物に含む場合はUERANSIMやカーネルモジュールの資料も必要です。
6. 実際の用途に対応するLGPLのリンク、AGPLのネットワーク経由ソース提供、SSPLのサービス／配布レビュー。SBOMや一般的なライセンス一覧だけでは不十分です。
7. 全レイヤー・履歴・ソースアーカイブの秘匿情報レビュー。生成資料にもローカルパス、上流のテスト用秘密情報、未確認情報が残り得ます。
8. OSサポート・依存指摘の処置、機能回帰試験の証跡、イメージ公開時の署名付き出所と匿名pullの確認、対象リリースに対する人による明示的な承認。

MongoDBは固定済み上流イメージのままで、永続データを変更しません。古いメジャーバージョンからの更新には別途検証したデータ移行が必要です。検査を通すためにメジャータグを差し替えたりDB volumeを削除したりしてはいけません。ビルダーのカーネルヘッダーに対する指摘も残します。ヘッダーは実行中カーネルではありませんが、パッケージ一致だけで悪用可能性を判断するものではありません。

## 2026-09-21の改善証跡と残作業

結果：依存・ビルド変更は検証済みですが、**配布全体の準備状況は引き続き保留（blocked）**です。19イメージの再検査は完了し、イメージ・設定・レイヤーの照合不一致や選択コンテナの変化はありませんでした。初回検査と脆弱性データベースのバイト列が一致しているため、以下は同じ条件で比較できます。件数はイメージ間で指摘ID・パッケージ・導入バージョンの組を重複除去したもので、CVE IDだけの件数や実証済み攻撃経路の数ではありません。

| 証跡 | 更新前 | 更新後 |
|---|---:|---:|
| HIGHの依存脆弱性候補 | 391 | 231 |
| CRITICALの依存脆弱性候補 | 21 | 7 |
| 秘密情報パターンの一致 | 10 | 1 |

更新したVinberoのPEイメージとWebUI以外のNF 10個では、HIGH/CRITICALの一致はありません。新しいNFイメージ11個すべてで秘密情報パターンの一致はありません。残る鍵1件はハッシュ照合済みのGoの公開テスト用鍵で、検査から除外していません。ビルダーの未使用npm配布物を除去したことで、その依存の指摘はスキャナーを無効化せず解消しました。秘密鍵のローテーションや、稼働volumeの検査・イメージへのコピーは行っていません。

残る依存候補を明示的に記録します。

- MongoDBの未変更の上流イメージ：HIGH 60件／CRITICAL 2件と古いOSベース。データを保持した互換性のある更新には、別の移行計画・試験が必要です。
- ビルダーのカーネルヘッダー：linux-libc-devにHIGH 166件／CRITICAL 5件。検査結果には修正版パッケージが示されていません。利用状況のレビューまたは互換性のある新しいビルド基盤が必要で、ホストカーネルへの指摘ではありません。
- WebUI：埋め込まれたfree5GC SMF moduleにHIGH 1件（CVE-2026-44321）。修正版は報告されていません。コンパイルや通信の成功は、この指摘の免除ではありません。
- 共通のbootstrap／observer／dashboard／controller／RANイメージには、実際に選択したPEデーモンの更新後も古いVinberoのコピーが残り、重複を除いてHIGH 4件です。コンポーネントのカスタマイズを保持して共通イメージ内のコピーを更新・再ビルドするか、実行時成果物を分割する必要があります。PEの更新だけでは、すべてのイメージや保持済み旧レイヤーを整理できません。

更新後の資料収集は19イメージ、レイヤー単位の通知2,663件、異なる通知本文349件を対象にしています。Go module 181件のうち179件でソースと通知を取得し、1件はZIPにライセンスファイルを検出できず、gosuの同じmoduleバージョン1件は取得できません。これらは非公開・未承認の資料であり、完成した再配布セットではありません。パッケージ情報に結び付かないファイル単位のライセンス検出も、別のレビュー要件として保持します。

コンパクト構成の全試験（新規1call、通常UPF／MUP、observer lease、PE再起動、ネットワーク再作成、neighbor復旧）と各コンポーネントの切り替え・パケット試験に合格しました。出所記録のフィールド修正後にAMFを再ビルドし、切り替えと実通信も合格しました。最終health確認はBGP peer 2台、observer lease、T1/T2、UE ping、新しいダッシュボード情報を確認しています。ローカル検査はPython 208件、Goテスト・vet、ShellCheck、日英ドキュメント、公開ソース一覧が合格しました。ソースと独自ツールの再ビルド結果の依存検査はポリシー指摘0件です。許可リスト内のソーススナップショットは、既存の厳密なテスト用鍵の例外を変更せず、秘匿値を伏せるGitleaks検査に合格しました。

fix-findingのレビューでは初回構築とコンポーネントビルドの両経路を追い、依存の最低バージョン、replace・バージョン形式、鍵ハッシュの不一致、ライセンス要件、アーカイブ境界の回帰試験を追加しました。独立エージェントによるレビューは利用できなかったため、別観点のローカルレビューを実施し、ファイル単位ライセンス要件の欠落を修正しました。CVEへの到達性を根拠にした免除は主張しません。コミット、push、新公開リポジトリ、バイナリ配布、DB移行は行っていません。旧イメージ、ソーススナップショット、検査記録は復旧・比較用に非公開で保持しています。

## 2026-09-23の新規自動構築イメージのレビュー

新しい初回自動構築を分離したクリーンVMで検証し、再起動前後の全パケット・復旧試験と、ダッシュボード／SMFの再ビルド・ロールバックも通りました。[単一VM構成の受け入れ結果](compact-lab.ja.md)を参照してください。初回NF構築は部品用ビルダーを共用し、一時領域での検証に成功してから完全な不変の基準イメージ一覧を選択します。独立したfix-finding調査・レビューと回帰試験で、既定の選択、失敗時の状態、独自指定、監査対象の網羅を確認しました。この経路では従来の上流NFイメージを選ぶ問題を修正済みです。既存ラボと独自イメージは無断で移行していません。

14イメージのアーカイブと空でないSBOM 14個を検証しました。監査は`complete: true`、`selection_unchanged: true`、`database_unchanged: true`、`policy_passed: false`、`publication_approved: false`で完了しています。Trivy `0.74.0`は更新日時`2026-09-23T01:09:35.013781075Z`のDBを使用しました。9月21日のDBとは異なるため、合計件数は同条件の変更前後比較ではありません。以下は指摘ID・パッケージ・導入バージョンの組を重複除去した件数です。

| イメージ群 | HIGH | CRITICAL | 秘密パターン一致 |
|---|---:|---:|---:|
| 8役割が使う新しい共通ランタイム | 0 | 0 | 0 |
| WebUIを除く10 NF | 0 | 0 | 0 |
| WebUI | 1 | 0 | 0 |

## 新しい候補のビルド入力の記録

新しいソースビルドでは、独自のGoプログラム4個、Vinbero／eBPF、UERANSIMも、部品開発と同じ権限を制限したビルダー内でコンパイルします。各ビルドは変更可能なチェックアウトを直接使わず、保存済みのソースを使用します。候補には、共通ランタイムの6件のビルド記録、ビルダーの識別情報、ビルド後のGo固定情報、スクリプト、ランタイム用レシピが記録されます。独自コードのライセンス・通知文も、イメージの外にソースと並べて保持します。収集ツールは共通ランタイムの9バイナリーも保存イメージと照合します。記録のない古い候補は不足のままとし、現在のチェックアウトから過去の由来を作ったことにはしません。

WebUIはビルドごとの新しいYarnキャッシュを使い、固定情報を変更しないインストールを維持し、実効的なフロントエンド固定情報と正確な依存ZIPを保存します。各ファイルとアーカイブのハッシュを記録し、ランタイムイメージ外に非公開でまとめます。収集ツールは記録されたファイル一式を照合し、パッケージのソースを展開・実行せず、内部の通知文のパスを数えます。通知文が検出されないものは明示し、ハッシュ一致をライセンス承認や上流由来の証明とは扱いません。スコープ付きパッケージ名に対応しつつ、ディレクトリー遡及は許可しません。由来資料が不完全なら、候補の採用前にビルドを失敗させます。

拡張後の収集ツールは、NF・共通ランタイム・フロントエンドの完了状態を分けて示し、全体の収集完了には3つすべての完了を要求します。それでも、対応ソース、リンク方法、ライセンス、ツールチェーンの網羅、署名、公開の認定ではありません。機能するビルドと配布判定の不合格は両立します。ランタイム、任意のビルダー、上流DB、履歴のないソース候補は別々に判断する必要があります。

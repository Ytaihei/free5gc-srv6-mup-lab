# pendingの研究タスク

[English](research-backlog.md) | 日本語

以下の実験的な拡張はpendingのままであり、納期の約束ではありません。一部には既存の部分実装や検証済みのベースラインがあるため、[機能の対応状況](feature-status.ja.md)で未実装・未検証の条件と区別します。移植性と保守を優先します。実装済みプロファイルと標準文書の正確な版は[研究範囲](research-scope.ja.md)、用語は[用語集](glossary.ja.md)を参照してください。

| 分野 | 対応を主張する前に必要な証拠 |
|---|---|
| 収束と障害復旧 | PFCP→BGP、BGP→eBPF、最初のパケットの時間を個別測定し、各制御/転送要素の再起動時の損失と復元状態を記録 |
| 複数加入者と移動 | 選択・非選択UE、終端変更、再登録を試験し、古い経路や加入者間の混線がないことを確認 |
| IPv6 UEとmobile behavior | AFI 2経路fixture、PFCP/アドレスモデル対応、該当SRv6 behaviorを通る双方向IPv6の実パケット証拠 |
| QoS/QFI | 受理PFCP更新が意図した経路・パケット処理になり、QFI変更や未対応の組み合わせを明示的に試験 |
| MUP経路/セグメントの拡張プロファイル | 固定したDraft/RFC版ごとに、独立したwire fixtureとPE転送試験で検証 |
| 運用上の強化 | 信頼するインターフェースを文書化し、広い配備範囲を主張する前に認証・認可、診断情報の秘匿化、資源上限を試験 |

単体試験は必要ですが、転送・切り替え・標準準拠の証明ではありません。通信に影響する実験では従来のUPFフォールバックを維持してください。

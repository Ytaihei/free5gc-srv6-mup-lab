# 移植可能なラボ設定

[English](portable-configuration.md) | 日本語

対応する構成は、Ubuntu 24.04上の6台のx86-64 KVM/libvirt VMと、core VM内のfree5gc-composeです。Composeだけではカーネルモジュール、隔離インターフェース、Vinbero XDPデータプレーンを再現できないため、libvirt XML、cloud-init、Ansibleで補います。稼働中のVMイメージは配布しません。

固定プロファイルはゲスト用17,408 MiBと、物理ホスト用の最低2,048 MiBの予備メモリーを必要とします。preflight、VM作成、VM起動はこの下限を満たさないホストを拒否します。swapは算入しません。24 GiB以上を推奨します。

## 設定の入口

`config/lab.example.yml` を管理対象外の `config/lab.local.yml` にコピーし、編集後に `./scripts/lab-config.py validate` を実行します。または、絶対パスを指定した `LAB_CONFIG` をexportします。選択順は `LAB_CONFIG`、`lab.local.yml`、管理対象のサンプルです。ローカルファイルは差分ではなく**完全な設定**であり、欠落したキーや未知のキーは検証エラーになります。

同じ設定を次に使用します。

- ホスト上のイメージディレクトリ、SSH鍵、ゲスト管理ユーザー
- VM名、管理用DHCP予約、libvirtブリッジ定義
- Ansibleの動的インベントリーとゲストのnetplan
- AMF/UPF/SMFのN2/N3アドレス、単一PLMN・スライス・DNN、IPv4 UEプール
- UERANSIM、MUPポリシー、BGP識別子/RD/RT、Vinbero SID設定
- 試験終端、ダッシュボード収集、任意のTailscale待ち受け

公開された加入者サンプルは隔離ラボだけで使ってください。実加入者の鍵やローカルの認証情報を管理対象サンプルへ入れないでください。マシン固有の上書き設定や生成したダッシュボード環境ファイルはコミット禁止です。

## 意図的に固定している部分

これは単一ホスト・単一UEのIPv4 Direct MUPトポロジーであり、汎用ネットワークオーケストレーターではありません。VMのインターフェース順、ゲスト内ソフトウェアの配置先、free5GC内部Dockerネットワーク（`10.100.200.0/24`）、N4キャプチャーインターフェース、APIポート9443、BGPポート179、SIDのビット割り当ては固定です。未対応のBGP/TEIDプレフィックスやロケーター長は検証で拒否します。名前とパスに使える文字は制限され、空白やシェル構文は使えません。

ゲスト管理ユーザー、管理アドレス/MAC、VM/ネットワーク名の変更は**新規配備向け**です。既存ゲストの名前変更やcloud-init再実行は行いません。稼働中の自動移行を期待して変更しないでください。ネットワーク定義ツールは、管理対象設定が異なるアクティブなネットワークの再定義を拒否します。トポロジー変更前に、影響するゲストとネットワークの停止を計画してください。ゲストやディスクを自動破棄することはありません。

プロビジョニングは固定Gitコミットの未変更free5GC設定を毎回読み、レンダリングします。変更済みYAMLに一度限りのホスト名置換を重ねる方式ではありません。古い生成設定はcoreゲストにバックアップします。加入者変更はWebUI APIで反映します。単一スライスのラボなので、上流の未使用の複数PLMN/スライス例は保持しません。

## ホスト準備とダッシュボード

独自設定でrootインストーラーを実行するときは、`sudo env LAB_CONFIG=/absolute/lab.local.yml LAB_HOST_USER="$USER" ./scripts/install-host-deps.sh` のように `LAB_CONFIG` を明示します。イメージディレクトリは専用の絶対パスにしてください。SSHの秘密鍵と公開鍵のパスは対で指定します。既存の秘密鍵がある場合、公開鍵がないことを理由に鍵を上書き再生成しません。

ダッシュボードの主待ち受け先はループバックだけです。Tailscaleは任意で、`host.dashboard.tailscale.enabled: false` ならループバックのみになります。有効でもインストール時にIPv4インターフェースがなければ、警告してループバックのみでインストールします。Tailscale接続後に再実行してください。ワイルドカードや物理LANでは待ち受けません。設定変更後は再起動・再インストールが必要です。

配備済みcore/controllerゲストの `mupctl` は、秘密情報を含まない `/etc/srv6-mup-controller-url` を読みます。`--server` と `MUP_CONTROLLER` で上書きできます。サービスの非公開設定へのファイルアクセス権を広げる必要はありません。

## 検証証跡と残る範囲

設定のレンダリングと不正入力は単体試験で確認します。既存の6 VMホストでは既定プロファイルの再適用を試験済みです。ただし、別マシンでのクリーンルーム復旧や、すべての非既定設定の組み合わせでのE2E動作を実証したものではありません。原文のR5完了条件は、2台目の対応KVMホストで全試験を通すことです。

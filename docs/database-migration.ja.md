# 単一VMのデータベース更新

[English](database-migration.md)

単一VM構成でDBを新規作成する場合は、固定したMongoDB 8.0.32を使います。ゲストにはAVX対応のx86-64 CPUが必要です。6VM参照構成のイメージlockは変更しません。既存の単一VMにMongoDB 4.4のボリュームがあれば、通常の起動では保持します。バージョンlockの変更をDB移行の代わりにはしません。

## コマンド

すべて同じプロファイルで実行してください。これらの操作中はラボの通信が中断します。

```sh
./lab database status
./lab database upgrade
./lab test all
./lab health
```

対象はラボの認証なし・単独構成のMongoDB 4.4で、FCVも4.4である場合です。認証、レプリケーション、capped collection、view、time-series、アプリケーションDB内のsystem collectionは別途移行の検討が必要です。既存データを加入者fixtureで置き換えて「保持できた」と判定するものではありません。

停止前に固定イメージを取得し、書き込み側とDBを停止して、ボリュームの所有・利用者を確認します。その後、停止中のデータを新しいボリュームへ複製します。複製先だけを4.4、5.0、6.0、7.0、8.0の順に更新します。中間サーバーはアプリケーションのネットワークに接続せず、TTLによる削除を無効にします。各段階でサーバー／FCVの版、collectionの整合性、BSON型を保持した文書のハッシュ・件数、インデックス、collection設定を照合します。比較には同じ固定クライアントを使い、旧版のインデックスにある冗長なnamespace情報だけを除きます。FCVがサーバーの管理情報を更新するため、内部DBのバイト一致は主張しません。

すべての照合が通ってから新しい選択を有効にし、WebUIログイン、SQNを保持した加入者設定の整合、実UEのRegistration、ICMP／HTTP疎通を確認します。元のボリューム、複製先、各段階のコンテナー、非公開の移行証跡を保持します。ボリュームの自動削除は行いません。

## 中断と復旧

```sh
./lab database recover
```

未完了のジャーナルがある間は通常起動・ビルド・部品のデプロイを停止します。切り替え前の復旧では元のDBを起動します。新しいDBへの書き込みが始まった可能性がある段階以降は、新しいボリュームを再開し、新しいデータを黙って破棄しません。復旧自体が失敗した場合もジャーナルを残します。このコマンドは任意時点へのロールバックではありません。

ゲストの`.lab/runtime/database/`にある非公開の選択記録・移行記録と、保持したボリュームを一緒に保全してください。新しいボリュームや移行証跡があるのに選択記録だけを失った場合、古いDBか新しい空DBかを推測せず起動を停止します。使うべきイメージとボリュームに対応する記録を確認して復元してください。チェックを回避するためにボリュームを消してはいけません。

切り替え後に古いバックアップへ戻すと、その後の書き込みが失われるため、別途明示的な運用判断が必要です。更新後のボリュームを古いMongoDBバイナリーで起動しないでください。汎用のバックアップ機能や本番DBへの対応を主張するものではありません。

## 検証と制約

2026-09-23に分離したラボで4.4.30から8.0.32へ移行し、すべての段階のアプリケーションデータ照合と実Registration・通信試験が通りました。個別試験では選択の永続化、選択記録を失った曖昧な状態、所有、停止した読み取り専用の複製元、失敗時のジャーナル、両段階の復旧を扱います。独立レビューで選択記録欠落時のフォールバック問題が見つかり、保持された旧データと新規の現行DBの両方を回帰試験に追加しました。

別の物理マシンでのクリーン導入は運用者の判断により今回の受け入れ対象から除外し、合格とは記録しません。研究機能の追加バックログは引き続きpendingです。イメージの再配布は別のレビューで扱います。[イメージ配布](image-distribution.ja.md)を参照してください。

段階的な移行は[MongoDB 8.0の更新手順](https://www.mongodb.com/docs/v8.0/release-notes/8.0-upgrade-standalone/)と[MongoDB 7.0の更新手順](https://www.mongodb.com/docs/v7.0/release-notes/7.0-upgrade-standalone/)に沿っています。これらはバイナリーの直接ダウングレードを許すものでも、アプリケーション試験を代替するものでもありません。
